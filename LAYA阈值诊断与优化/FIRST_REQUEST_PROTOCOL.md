# 首次请求门控的有限范围候选

登记于 左右，基于state0/1每回合仅第一次请求的开发分支分析；state2模型系数已冻结，state2分支采集中，尚未查看其新分支结果或分数。

新方法laya_first每回合只询问LAYA一次：首次Smol70请求机会I=0.3H时，以原二项argmax决定请求或跳过；continue时等到2I请求，之后无条件恢复Smol70。它与每个新计划都允许跳过一次的laya_skip1不同。该有限策略用于检验LAYA在早期决策中的价值，并限制总门控费用；不能将结果泛化为全程自适应调度。

在20个已曝光开发起点/H上，binary_window3首次门控的成功数为11/9/6，Smol70为8/8/7；VLA调用为219/121/66，对照249/129/68。所有双失败和提前结束的回合均在分母内。此分析只组合已实际执行的一个分支，不叠加多个干预机会；没有包含门控费用，不是实测服务加速。H50值得验证，H200已有损失；不得只保留H50表格。

仅晋升未经适配的window3首次门控作为该机制的开发候选，原compact首次门控保留归因控制。先各用task0/state0、三种H做六回合真实执行资格，要求与已存prefix+所选分支的动作/物理状态完全相同、LAYA选择与原离线输入相同。最终总服务费用和泛化仍须由state10–14的配对验证判断；若其中再改策略，该组转为开发并另设验证起点。
