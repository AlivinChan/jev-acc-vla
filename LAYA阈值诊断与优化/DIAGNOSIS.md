# LAYA低置信度诊断

远端RTX4090 D，冻结原LAYA检查点与SDK0.3.22。对旧90条开发轨迹各取首、中、末门控，共270条；6变体共1620个实测机器人状态判断，另有60个明确语义控制判断，warmup另记。原始输出见raw/diagnosis_v1，汇总见analysis/diagnosis_summary.json。该诊断没有新的机器人成功标签。

“原3选项”指前轮服务模板额外设置了uncertain，并不是LAYA模型固有的类别数。当前主闭环已经改为continue/replan真正二选项。SDK日志另有choice:11+温度被夹限的警告，本实验实际使用choice:2和choice:3-5桶，实测值有效；那个警告不解释本次低分。

原3选项270条概率与历史记录逐值一致，最大误差0；原逻辑使用max(probabilities)，没有误用SDK的归一化熵confidence。SDK从原logits除以选项桶温度再softmax，本次逐项重算与返回值四舍五入误差≤0.00006。三选项温度1.76015，二选项1.90636；不同问题不能把返回分数直接当成跨任务准确率。温度人为降低不构成校准。

确认一个输入错误：float32先round再tolist会重新暴露二进制小数尾巴，原意三位的动作变成17位。改为float64后round，保留原定精度、降低约19.0%的token，并改变86/270个argmax。修复合理且保留，但它没有解决0.7弃权问题。

排除本批提示词截断假设：所有变体head_dropped=0、state截断=0。SDK的usage确实只报告state截断，因此增加独立head审计有价值，但不得将本轮低置信度归因于实际并未发生的截断。

长版二选项虽然有146/270越过0.7，却270/270全部选择continue；10条明确语义控制仅7条正确，原3选项为9条。短版二项控制也是7/10；这些只是人工语义探针，不足以测机器人决策准确率。不能把更大的数字宣称为可信度修复。

现有证据支持的解释：数值输入冗长确有影响；问题格式和选项描述对这个通用文本判别器影响很大；它没有在本机器人门控域上得到有效校准。是否真正做出有用判断，需要相同初态的闭环实验，以及必要时有真实分支结果的标签。后续按用户授权采用严格二选项argmax，固定选项顺序，不以0.7拒绝所有输出。

优先用闭环pilot比较长版、短版、紧凑版，以及只在有限队列将耗尽时请求的对照。冻结VLA继续保持；前一轮报告和原始结果只读。

实现依据：本地留存的source_snapshot/sdk_agent.py、sdk_common.py和sdk_confidence.py及其哈希；固定公开模型说明：[LAYA pinned model card](https://huggingface.co/convaiinnovations/laya/blob/55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851/README.md)，[官方SDK](https://github.com/NandhaKishorM/laya)。文档与本地代码均不能替代当前机器人任务上的校准证据。

二项分数的数值条件也已明确：在固定T≈1.90636下，max(p)≥0.7要求两项原始logit差的绝对值至少T×log(0.7/0.3)≈1.615。观测到的短/紧凑输入通常没有这样的间隔。更换格式或拟合校准虽能增大分数，但冻结后的state2诊断里，选中线性读出漏掉全部18个需要重规划的有判定机会。完整564机会/1,128分支的标签诊断见REPORT第5节；该负结果支持保留原始二项argmax，而非宣称0.7已获可靠修复。
