# 类别平衡读出的有限开发检查

主验证v2仍执行且尚未汇总。旧calibrators_v1和所有主/补充队列保持冻结，已有state2评价原件不覆盖。

原总体对数损失读出全选继续，可能同时包含类别不平衡和特征辨别力不足。仅为区分这两点，固定检查binary_window3的一种外部线性读出：输入仍为冻结LAYA已有scorer GELU后、两个语义选项的1024维特征差；训练state0的utility可判定标签，排除双失败。每类总权重各占一半，平均加权log loss加L2，惩罚固定[0.01,0.1,1,10]。不增加变体、调温或另试阈值，推理仍是两个输出取大者（精确平局重规划）。VLA和基础LAYA权重都不更新。

该目标改变训练类别先验。输出只能标为类别平衡决策分数，不能将其跨过0.7解释为已得到实际正确率校准。

先以state1筛选，四个模型均保存：重规划召回和平衡准确率均不得低于原window3，同时两类召回均须非零。对state1每task/H首次请求的已存完整反事实分支，同H成功数均不得少于原window3，三H总VLA调用须严格减少。只在满足全部条件的模型中按总调用较少、平衡准确率较高、正则较强顺序选最多一个。首次门控所有候选门控次数相同；这仍不包含部署特征捕获开销，不能作为完整服务提速结果。

系数及选择结果冻结后，才读取state2做只读诊断。state2已经用于旧模型诊断，不能声称是本项目未曝光测试集；不据其结果改模型、阈值或正则。若state2同H首次门控成功数或总调用方向退化，拒绝部署。通过也仅有下一步真实门控资格，必须另开新候选队列、记录全部计算费用并使用新的配对初态，不能改变当前主验证结论。

没有模型通过state1则停止这一家族，不继续读取state2以找例外。
