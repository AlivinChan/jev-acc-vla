# 二项选项顺序诊断

在主验证仍进行、未汇总方法成绩时登记。当前冻结候选和正在执行的验证不改动。本检查只有LAYA离线推理，无VLA训练或新机器人成功率测量。

问题：固定排列的两个选项在同一双向编码输入中具有不同位置。仅交换排列会不会显著改变语义标签对应的概率，或暴露SDK标签映射错误？原始argmax应按“继续／重规划”的语义标签解释，不能按第一个／第二个槽位解释。

完整预定输入：原diagnosis_v1的binary_full、binary_short、binary_compact各280条（270真实开发状态＋10明确语义控制）；再加入scores_window_train_v1中全部189条state0的binary_window3真实输入。共1,029条，每条原顺序和逆顺序各一次，2,058次判断；8次分格式、分顺序warmup单列。保留已变换后的最终model_state字节，不能再次compact而意外删除对象信息。

使用同一冻结LAYA、原SDK温度、相同问题文字与token预算，唯一干预为SDK明确支持的option_order=[0,1]或[1,0]。原顺序须复现已存概率和选择；捕获槽位logits，独立softmax再按语义标签还原，核对SDK输出。前后参数SHA相同、所有head和state无截断、无CPU fallback。逐输入交替两种执行顺序，避免单边warmup影响。

只报告每种格式的选择一致率、语义p(replan)差值分布、置信度变化、明确语义控制成绩和单次完整SDK费用。真实状态没有新正确性标签，不因逆序较高置信就晋升策略。若以后尝试顺序集成，必须另设包括双次推理费用的闭环候选与控制，不把本诊断称为效率收益。
